# 中文模型指纹（model-fingerprints-zh）——骨架与积累方法

**状态：骨架版（v0）。** 中文输出指纹目前**只有少量本地观察**，多数条目待积累。英文/繁中指纹见 sepia 的 model-fingerprints.md（双层结构的方法论来源，台账 SEPIA-2026）。

## 框架（沿用 sepia 双层结构）

- **叙事层（待实测）**：模型在中文叙事输出中偏离「其他 AI」的签名特征。sepia 的叙事层指纹来自 StoryScope §5 Table 17（英文实测，六向归因 68.4% F1）——**中文叙事层无对应实测**，本层条目从零积累。
- **文体层（观察 + vendor 指导）**：模型中文输出的句法/词汇/排版倾向。来源分三档：`本地观察`（编辑实践，单例）、`多例确认`（≥3 篇独立文本出现）、`vendor 声明`（模型官方文档，注明版本与引用日期）。

## 角色与规则（对齐 SKILL.md）

- **author**（谁写了手上的文本）与 **executor**（本次修订用什么模型）分开判定，判定只走元数据，不从文风推断（SKILL.md「模型身份只依据元数据判定」条款）。
- **operative vs prior**：指纹条目带模型版本标签，版本匹配才是 operative（生效指纹）；不匹配的作为 prior（历史参照），只用于对照草稿，不用于判定当前文本。
- 指纹未覆盖的语言/模型：按通用模式处理，不做模型特判。

## 指纹积累方法（如何把「待积累」变成条目）

1. **记录**：编辑实战中遇到「这个特征很像某模型的中文输出」→ 记录文本片段（脱敏）、模型与版本（元数据确认的）、出现次数。
2. **升级**：单例 = 本地观察；≥3 篇独立文本 = 多例确认，入表。
3. **校验**：有条件时做对照生成（同 premise 让候选模型生成中文样本，比对特征是否复现）——复现才算「签名」，不复现的是通用 AI 味（归回通用模式）。
4. **入表**：写明层（叙事/文体）、特征描述、反例（什么情况不算）、版本标签。
